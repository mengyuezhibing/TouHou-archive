# Touhou Resource Studio · 东方资源研究工作台

面向东方 Project 同人游戏开发者的综合工具：**游戏归档解包 → 资源解析 → 素材研究 → 创作辅助 → 引擎导出**。

不是"素材查看器"，而是「资源研究 + 弹幕分析 + Roguelite 设计工具 + 同人开发助手」的组合。

---

## 核心能力

### 归档解包

按 thtk（Touhou Toolkit）权威格式实现，**非猜测性适配**：

| 作品 | 归档格式 | 状态 |
|---|---|---|
| TH06 | PBG3 | 完整支持（位流索引表 + LZSS） |
| TH07 | PBG4 | 完整支持 |
| TH08 / TH09 | PBGZ | 完整支持（头部解混淆 + 末尾加密表 + 按类型解密） |
| TH09.5 / TH10+ | — | 加解密算法与参数表已就位，归档表结构未完成 |

核心算法严格对照 thtk 源码实现：

- `core/bitstream.ts` — MSB-first 位流 + 变长整数（2 位长度码 + 1~4 字节）
- `core/lzss.ts` — LZSS 编解码（窗口 8192 / 最小匹配 3 / 偏移 13 位 / 长度 4 位 / 偏移 0 终止）
- `core/crypt.ts` — `th_crypt` 分块置换 + XOR，含 5 部作品的参数表
- `core/png.ts` — 零依赖 PNG 编解码 + 画布合成
- `core/jpeg.ts` — TH06/TH07 的 JPEG 贴图解码 + 黑底转透明

### 资源解析

- **ANM 动画**：同时支持原始 ZUN 格式与 thtk 重编译格式（后者为 64 字节头 + THTX 内嵌纹理 / 外置 PNG 引用两种变体），还原动画脚本帧序列，生成 TexturePacker JSON Hash 图集
- **ECL 弹幕**：真正的**指令级反汇编**（头部强校验 → 按终止标记精确切分 → 仅在指令参数区内提取弹幕参数），非字节级盲目扫描
- **MSG 文本**：Shift-JIS / UTF-8 自动判定，对话与说话人提取
- **BIR 中间表示**：弹幕归一化为与引擎无关的 BIR，再驱动模拟 / 编辑 / 导出

### 研究数据库

25 张表（SQLite），含 `Tag`/`Resource_Tag` 多对多、`Bullet_Action` 动作时间轴、`Animation`/`Animation_Frame` 帧序列、`Character_Asset` 角色素材关联。

自动分类填充：从解包资源出发，自动构建角色库 / 怪物库 / Boss / 符卡库 / 文本分析。角色身份识别以**符卡名**为锚点（`氷符「アイシクルフォール」`只可能属于琪露诺），而非依赖版本间不稳定的文件编号。

### 创作辅助

弹幕编辑器（参数 + 时间轴）、Boss 阶段性编排、武器成长曲线、局外成长经济模型、Godot / Unity / JSON 导出。

## 快速开始

```bash
# 安装依赖
npm install
npm --prefix server install
npm --prefix web install

# 生成演示数据集（合成符合真实 PBG3 格式的游戏文件）
npm --prefix server run seed

# 启动（后端 8787 + 前端 5173）
npm run dev
```

打开 http://127.0.0.1:5173

### 使用真实游戏文件

1. 「游戏库」→ 扫描游戏目录
2. 「解包中心」→ 选择归档 → 解包
3. 「识别目录独立文件」→ 收录散落的 BGM 等
4. 「自动分类填充」→ 构建角色 / 怪物 / 符卡 / 文本
5. 「识别角色身份」→ 依据符卡名确定角色

### 自检

```bash
npm --prefix server run verify
```

校验产物完整性（文件存在性、尺寸匹配、图片可解码）。**注意：它只验证内部一致性，不验证格式正确性**——格式正确性需用真实游戏文件验证。

## 设计说明

### 配色

取自「沙绿 · 奶油 · 金瞳」自然色系：

| 用途 | 色值 |
|---|---|
| 主强调（瞳孔金） | `#b8902a` |
| 次强调（沙绿） | `#7da266` |
| 主文本（奶油） | `#f3f1e2` |
| 背景（深橄榄黑） | `#0e100c` |

### 关于自适应探测

早期版本采用"多布局自适应探测 + 魔数扫描兜底"。对照 thtk 后确认这**不可靠**——PBG3 的魔数会让探测安全失败（`count` 超限），静默退化成魔数扫描。现在按魔数严格分派，探测仅作兜底。

### 本地优先

整个工具不依赖任何外部服务：

```
原始游戏文件（本地磁盘任意路径）
        ↓  读取
   归档解析（本机 Node 进程）
        ↓  写入
   Data/（数据库 · 精灵 · 图集 · 音频 · 分析结果）
        ↓  经 /files 提供给界面
      浏览器
```

服务默认**只监听回环地址**，跨源请求**仅接受本地来源**，数据库文件不通过静态服务提供：

```bash
npm run dev                # 仅本机可访问（默认）
HOST=0.0.0.0 npm run dev   # 需要从局域网 / 移动端访问时
```

这样处理的原因：本服务能读本地磁盘、能触发解包，若监听全网卡且 CORS 全开，任何你访问的网页都能在后台请求 `127.0.0.1:8787`，读取素材或翻你的目录。

## 开发状态

### 已完成

游戏扫描 · 归档解包（PBG3/PBG4/PBGZ）· 图片/音频/文本提取 · ANM 解析与图集 · ECL 指令级反汇编 · 弹幕模拟 · 符卡库 · BGM · 文本分析 · 角色/怪物自动分类 · 身份识别 · 25 张表数据库 · 15 个界面视图 · 导出中心

### 待完成

- **TH10+ 归档表结构**：解密算法与参数表已就位，缺 `thdat95.c` / `thdat12.c` 等对应的表结构
- **ANM 动画脚本指令流**：贴图与区域表已准确，完整帧序列还原需要 thanm 的参数类型表
- **STD 场景解析**：pytouhou 已有完整结构定义，尚未实现
- **拖拽式时间轴编辑**：目前是参数编辑 + 时间轴展示

### 已知限制

- 部分汉化 / 重打包版本是**增量包**（thcrap 只打包修改过的资源），原版贴图需另行提供
- 立绘编号与角色的对应关系在不同版本间不稳定，识别以符卡名为准
